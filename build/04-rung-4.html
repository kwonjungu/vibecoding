STEP 04

주소 만들기

여기가 연수의 정점입니다. 지금까지 만든 앱에 인터넷 주소를 답니다. 주소가 생기면 QR 하나로 학생 30명이 같은 앱을 엽니다. 앱의 형태에 따라 길이 둘로 갈리니 어느 쪽인지 먼저 판단합니다.

왜 필요한가

홀도 꾸몄고 재료도 넣었습니다. 그런데 지금 그 앱은 내 노트북에서만 열립니다. 옆자리 선생님 휴대폰으로는 열리지 않습니다. 파일이 그 노트북 안에만 있기 때문입니다.

식당으로 치면 홀은 다 꾸몄는데 건물에 주소가 없는 상태입니다. 아이들이 들어올 문이 아직 없습니다. 이 칸에서 그 문을 냅니다. 주방은 다음 칸에서 짓습니다.

문 내는 방법은 앱의 형태에 따라 갈립니다. 3칸에서 파일 한 개가 폴더로 늘어난 그 갈림입니다. 앱 파일 한 개짜리와 폴더로 이루어진 앱은 올리는 곳이 다릅니다. 그래서 두 길을 나란히 싣습니다.

공개 전에 한 번 멈춥니다. Public 저장소는 전 세계에 공개됩니다. 학생 이름과 얼굴 사진은 올리지 않습니다. 교과서 지문과 삽화가 들어간 앱은 교실 안에서만 씁니다.

이렇게 합니다

메모장으로 열리는 앱 파일 한 개면 길 A, AI가 폴더를 만들어 줬으면 길 B입니다.

길 A. 파일 한 개는 깃허브 페이지

  1. github.com 오른쪽 위 더하기 버튼에서 New repository를 고릅니다.
  2. Repository name은 영문 소문자와 숫자, 하이픈만 씁니다.
  3. Public을 고르고 Add a README file은 체크하지 않은 채 Create repository를 누릅니다.
  4. 가운데 uploading an existing file 링크를 누릅니다.
  5. index.html과 assets 폴더를 함께 골라 끌어다 놓습니다. 하나씩이 아니라 폴더째입니다.
  6. 목록에 assets가 붙은 줄을 확인하고 Commit changes를 누릅니다.
  7. Settings 탭에서 왼쪽 Pages를 누릅니다.
  8. 아래 표대로 세 칸을 맞추고 Save를 누릅니다.
  9. 1분에서 3분 뒤 Actions 탭에 초록 체크가 붙으면 완료입니다.
길 A 설정값입니다. Settings 탭의 Pages 메뉴, Build and deployment 칸에 있습니다.

길 B. 폴더 프로젝트는 ai.studio

5칸부터 7칸까지 이 길입니다.

  1. AI Studio의 Build 화면에서 내 프로젝트를 엽니다.
  2. 오른쪽 위 배포 버튼을 누릅니다.
  3. ai.studio로 시작하는 주소가 나오면 복사합니다.

받은 사람은 계정 없이 엽니다. 공개 범위는 길 A와 같습니다.

Starter Tier는 결제 수단 없이 쓰고 무료 배포는 계정마다 두 번입니다. 넘으면 요금이 붙어, 오래 열어 둘 앱은 길 A가 안전합니다.

두 길이 다 막히면 Netlify Drop에 앱 폴더를 끌어다 놓습니다. 주소는 무작위로 생깁니다. 앱이 없으면 아래 묶음을 받아 폴더째 놓습니다.

해 보기, 나만의 구슬 뽑기

공개된 구슬 뽑기를 우리 반 것으로 바꿔 봅니다. 빌드는 깃허브가 합니다.

  1. github.com/lazygyu/roulette 에서 오른쪽 위 Fork를 누릅니다. 저장소 이름은 roulette 그대로 둡니다.
  2. Actions 탭에서 초록 버튼을 눌러 자동 실행을 켭니다.
  3. index.html 의 연필 아이콘을 누르고 <title> 안의 이름을 우리 반 이름으로 바꿉니다. 라이선스 의무입니다.
  4. 같은 파일 위쪽 umami 로 시작하는 줄 두 개를 지웁니다. 남기면 접속 기록이 원저자 통계로 넘어갑니다.
  5. 초록색 Commit changes를 누릅니다.
  6. Actions 탭에서 초록 체크를 2분에서 3분 기다립니다.
  7. Settings의 Pages에서 Branch를 gh-pages 로 고르고 저장합니다.
  8. https://[아이디].github.io/roulette/ 를 열고 이름 칸에 우리 반 명단을 붙여넣습니다.

더 고치려면 구슬이 굴러가는 판인 src/data/maps.ts 를 봅니다. 고쳐 커밋하면 다시 빌드됩니다.

남의 것을 쓰는 법

공개와 마음대로 써도 된다는 말은 다릅니다. LICENSE 와 README 를 먼저 읽습니다.

고쳐서 다시 배포해도 됩니다. LICENSE 파일의 저작권 고지는 지우지 않습니다.

마블 룰렛이라는 이름은 저자의 상표입니다. MIT 대상이 아니니 반드시 다른 이름을 씁니다.

만든 사람 밝히기

페이지 아래에 원본이 어디 것인지 한 줄 남깁니다.

복붙 설정값

이 칸에서 옮겨 적을 것은 프롬프트가 아니라 설정값입니다. Pages 화면에서 아래 세 줄을 그대로 맞추면 주소가 나옵니다.

Source: Deploy from a branch
Branch: main
Folder: / (root)

완성 주소: https://[아이디].github.io/[저장소명]/
[아이디]는 내 GitHub 사용자명, [저장소명]은 방금 만든 저장소 이름입니다.

이러면 성공입니다

  • 주소를 새 탭에 붙여넣으면 내 앱이 열립니다.
  • 휴대폰에서 같은 주소를 열어도 똑같이 열립니다.
  • assets 폴더의 그림이 깨지지 않고 그대로 보입니다.

막히면

주소를 열면 404가 뜹니다

증상 404 화면이 나옵니다.

원인 Save 직후에는 켜지는 데 1분에서 3분 걸립니다.

해결 기다렸다 새로고침합니다. Actions 탭의 pages build and deployment에 초록 체크가 붙었는데도 404면 주소 끝 슬래시와 철자를 봅니다.

그림만 안 보입니다

증상 글자와 버튼은 나오는데 그림 자리가 빕니다.

원인 assets 폴더 구조가 깨졌거나 파일명 대소문자가 코드와 다릅니다.

해결 assets 폴더가 없으면 폴더째 다시 올리고, 파일명은 영문 소문자로 통일합니다.

Pages에 Branch 선택지가 없습니다

증상 main을 고를 칸이 없거나 유료 안내가 뜹니다.

원인 Private 저장소라 무료 계정은 페이지를 켤 수 없습니다.

해결 Danger Zone의 Change visibility로 Public으로 바꿉니다. 바꾸기 전에 학생 이름과 얼굴 사진, 교과서 지문이 없는지 봅니다.

액션은 초록 체크인데 페이지가 404입니다

증상 빌드는 성공인데 404입니다.

원인 포크한 룰렛은 결과가 gh-pages 에 쌓이는데 Pages 브랜치가 main 입니다.

해결 Branch를 gh-pages 로 바꾸고 저장합니다.

액션이 빨간 엑스로 끝납니다

증상 배포 단계에서 권한 오류가 나고 gh-pages 가 안 생깁니다.

원인 액션이 쓰기 권한을 못 받았습니다.

해결 Settings의 Actions, General에서 Workflow permissions를 읽고 쓰기로 바꿔 다시 실행합니다.

화면이 하얗게만 나옵니다

증상 열리는데 아무것도 없습니다.

원인 저장소 이름을 바꿨습니다. 빌드 설정이 roulette 을 경로로 씁니다.

해결 이름을 roulette 로 되돌리고 액션을 다시 실행합니다.
