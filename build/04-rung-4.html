STEP 04

주소 만들기

여기가 연수의 정점입니다. 지금까지 만든 앱에 인터넷 주소를 답니다. 주소가 생기면 QR 하나로 학생 30명이 같은 앱을 엽니다. 앱의 형태에 따라 길이 둘로 갈리니 어느 쪽인지 먼저 판단합니다.

왜 필요한가

홀도 꾸몄고 재료도 넣었습니다. 그런데 지금 그 앱은 내 노트북에서만 열립니다. 옆자리 선생님 휴대폰으로는 열리지 않습니다. 파일이 그 노트북 안에만 있기 때문입니다.

식당으로 치면 홀은 다 꾸몄는데 건물에 주소가 없는 상태입니다. 아이들이 들어올 문이 아직 없습니다. 이 칸에서 그 문을 냅니다. 주방은 다음 칸에서 짓습니다.

문 내는 방법은 앱의 형태에 따라 갈립니다. 3칸에서 파일 한 개가 폴더로 늘어난 그 갈림입니다. 앱 파일 한 개짜리와 폴더로 이루어진 앱은 올리는 곳이 다릅니다. 그래서 두 길을 나란히 싣습니다.

공개 전에 한 번 멈춥니다. Public 저장소는 전 세계에 공개됩니다. 학생 이름과 얼굴 사진은 올리지 않습니다. 교과서 지문과 삽화가 들어간 앱은 교실 안에서만 씁니다.

이렇게 합니다

판단 기준은 한 문장입니다. 메모장으로 열 수 있는 앱 파일 한 개면 A, AI가 폴더를 만들어 줬으면 B입니다.

길 A. 앱 파일 한 개를 깃허브 페이지로

메모장으로 열리는 index.html 한 개짜리 앱입니다. 깃허브 페이지를 켜서 주소를 받습니다. 주소가 내 것이고 오래 남습니다.

  1. github.com에 로그인하고 오른쪽 위 더하기 버튼에서 New repository를 고릅니다.
  2. Repository name은 영문 소문자와 숫자, 하이픈만 씁니다. 이 이름이 주소 끝에 그대로 붙으니 짧게 짓습니다.
  3. Public을 고릅니다. Add a README file은 체크하지 않습니다. 그다음 Create repository를 누릅니다.
  4. 다음 화면 가운데의 uploading an existing file 링크를 누릅니다.
  5. 탐색기에서 index.html과 assets 폴더를 함께 선택해 브라우저 화면으로 끌어다 놓습니다. 파일 하나씩이 아니라 폴더째 끌어다 놓습니다.
  6. 목록에 assets가 앞에 붙은 줄이 보이는지 확인하고 아래 Commit changes를 누릅니다.
  7. 저장소 위쪽 Settings 탭을 누르고 왼쪽 사이드바에서 Pages를 누릅니다.
  8. 아래 표대로 세 칸을 맞추고 Save를 누릅니다.
  9. 1분에서 3분 기다립니다. 404가 뜨면 새로고침합니다. Actions 탭에서 초록 체크가 붙으면 완료입니다.
길 A 설정값입니다. Settings 탭의 Pages 메뉴, Build and deployment 칸에 있습니다.

주소https://[아이디].github.io/[저장소명]/끝 슬래시까지 붙입니다

길 B. 폴더 프로젝트를 ai.studio 주소로

AI가 src 폴더와 여러 파일을 만들어 준 앱입니다. 이런 앱은 깃허브에 올려도 그냥 파일 묶음으로만 보입니다. AI Studio Build 화면에서 바로 배포하는 쪽이 빠릅니다.

  1. AI Studio의 Build 화면에서 내 프로젝트를 엽니다.
  2. 오른쪽 위 배포 버튼을 누릅니다.
  3. 잠시 뒤 ai.studio로 시작하는 주소가 나옵니다. 그 주소를 복사합니다.
  4. 주소만 보내면 다른 사람이 바로 들어옵니다. 따로 계정을 만들 필요가 없습니다.

5칸부터 7칸까지는 모두 이 길로 갑니다. 세 칸 다 AI Studio Build로 만드는 폴더 프로젝트이기 때문입니다.

배포한 주소도 링크를 받은 사람이면 누구나 엽니다. 공개 범위는 길 A와 같습니다.

쉬운 길이지만 무료로 쓸 수 있는 양이 정해져 있습니다. Starter Tier로 결제 수단 없이 바로 올릴 수 있고, 여기에 더해 계정마다 무료 배포가 두 번 주어집니다. 그 범위를 넘으면 쓴 만큼 요금이 붙습니다. 한 학기 내내 열어 둘 앱이라면 길 A가 안전합니다. 공개 저장소로 올린 깃허브 페이지는 요금이 없습니다.

두 길이 모두 막히면 플랜 C가 있습니다. Netlify Drop에 내 앱 폴더를 통째로 끌어다 놓으면 몇 초 만에 주소가 나옵니다. 로그인도 필요 없습니다. 다만 주소가 무작위로 만들어지고 내 계정에 묶이지 않으니, 오래 쓸 주소는 길 A로 다시 냅니다.

깃허브는 창고만이 아닙니다

지금까지 깃허브를 파일을 올려 주소를 내는 곳으로만 썼습니다. 역할이 둘 더 있습니다. 이 둘을 알면 남이 만든 것을 내 수업에 맞게 고쳐 쓸 수 있습니다.

창고

파일을 모아 두는 곳입니다. 길 A에서 앱 파일 한 개와 재료 폴더를 올렸습니다.

복사기

남이 만든 저장소를 통째로 내 계정에 복사합니다. 포크라고 합니다. 원본은 그대로 있고 복사본만 내 것이 됩니다.

공장

내 컴퓨터 대신 깃허브가 코드를 만들어 줍니다. 액션이라고 합니다. 설치할 것이 없습니다.

해 보기, 나만의 구슬 뽑기

공개된 구슬 뽑기 프로그램 하나를 가져와 우리 반 것으로 바꿔 봅니다. 코드를 몰라도 됩니다. 브라우저에서 글자 몇 줄만 고칩니다. 빌드는 깃허브가 합니다.

  1. github.com/lazygyu/roulette 에 들어가 오른쪽 위 Fork를 누릅니다. 저장소 이름은 roulette 그대로 둡니다. 이름을 바꾸면 화면이 하얗게 뜹니다. 빌드 설정이 이 이름을 경로로 쓰고 있기 때문입니다.
  2. 복사된 내 저장소에서 Actions 탭을 엽니다. 포크한 저장소는 자동 실행이 꺼져 있습니다. 초록 버튼을 눌러 켭니다.
  3. index.html 을 열고 연필 아이콘을 누릅니다. <title> 안의 이름을 우리 반 이름으로 바꿉니다. 이건 취향이 아니라 의무입니다. 아래 라이선스 항목을 보세요.
  4. 같은 파일 위쪽의 umami 로 시작하는 줄 두 개를 지웁니다. 남겨 두면 우리 반 학생들이 접속한 기록이 원저자의 통계로 넘어갑니다.
  5. 초록색 Commit changes 버튼을 누릅니다. 누르는 순간 깃허브의 공장이 돌기 시작합니다.
  6. Actions 탭에서 초록 체크를 기다립니다. 2분에서 3분쯤 걸립니다. 내 노트북은 아무 일도 하지 않습니다.
  7. Settings의 Pages에서 Branch를 gh-pages 로 고르고 저장합니다. 길 A와 다릅니다. 빌드 결과가 그 브랜치에 따로 쌓이기 때문입니다.
  8. https://[아이디].github.io/roulette/ 를 엽니다. 이름 칸에 우리 반 명단을 붙여넣고 돌려 봅니다.

더 고치고 싶으면 src/data/maps.ts 를 봅니다. 구슬이 굴러가는 판입니다. 한 줄 고치고 커밋하면 다시 빌드되어 주소에 반영됩니다. 이 왕복이 바이브코딩에서 한 번에 하나씩 고친다는 원칙과 같습니다.

남의 것을 쓰는 법

이 실습에서 가장 중요한 부분입니다. 공개되어 있다는 말과 마음대로 써도 된다는 말은 다릅니다. 저장소의 LICENSE 와 README 를 먼저 읽습니다.

코드는 MIT

가져다 쓰고 고치고 다시 배포해도 됩니다. 다만 저작권 고지를 지우면 안 됩니다. LICENSE 파일은 그대로 둡니다.

이름은 상표

마블 룰렛이라는 이름은 저자의 상표입니다. 국내에 출원 중입니다. 코드는 MIT지만 이름은 라이선스 대상이 아닙니다. 반드시 다른 이름을 씁니다.

만든 사람 밝히기

우리 반 페이지 아래에 원본이 어디 것인지 한 줄 남깁니다. 라이선스가 요구하는 일이자 아이들에게 보여 줄 태도입니다.

복붙 설정값

이 칸에서 옮겨 적을 것은 프롬프트가 아니라 설정값입니다. Pages 화면에서 아래 세 줄을 그대로 맞추면 주소가 나옵니다.

Source: Deploy from a branch
Branch: main
Folder: / (root)

완성 주소: https://[아이디].github.io/[저장소명]/
[아이디]는 내 GitHub 사용자명, [저장소명]은 방금 만든 저장소 이름입니다.

이러면 성공입니다

  • 주소를 새 탭에 붙여넣으면 내 앱이 열립니다.
  • 휴대폰에서 같은 주소를 열어도 똑같이 열립니다.
  • assets 폴더의 그림이 깨지지 않고 그대로 보입니다.

막히면

주소를 열었더니 404가 뜹니다

증상 주소창에 붙여넣었는데 앱 대신 404 화면이 나옵니다.

원인 Save를 누른 직후에는 아직 간판이 켜지지 않았습니다. 켜지는 데 1분에서 3분 걸립니다.

해결 잠시 기다렸다가 새로고침합니다. 저장소 Actions 탭을 열어 pages build and deployment 작업에 초록 체크가 붙었는지 봅니다. 체크가 붙었는데도 404면 주소 끝 슬래시와 저장소 이름 철자를 확인합니다.

앱은 열리는데 그림만 안 보입니다

증상 글자와 버튼은 나오는데 배경 그림이나 캐릭터 자리가 비어 있습니다.

원인 파일을 하나씩 올려 assets 폴더 구조가 깨졌거나 파일명 대소문자가 코드와 다릅니다. 내 노트북은 대소문자를 가리지 않지만 서버는 가립니다.

해결 저장소 목록에 assets 폴더가 보이는지 확인합니다. 없으면 폴더째 다시 올립니다. 파일명은 영문 소문자로 통일하고 코드 안 경로와 한 글자씩 맞춥니다.

Pages 메뉴에 Branch 선택지가 없습니다

증상 Settings에서 Pages를 열었는데 main을 고를 칸이 보이지 않거나 유료 안내가 뜹니다.

원인 저장소를 Private로 만들었습니다. 무료 계정은 Private 저장소에서 깃허브 페이지를 켤 수 없습니다.

해결 Settings 맨 아래 Danger Zone에서 Change visibility를 눌러 Public으로 바꿉니다. 바꾸기 전에 학생 이름과 얼굴 사진, 교과서 지문과 삽화가 파일 안에 없는지 먼저 확인합니다.

액션은 초록 체크인데 페이지가 404입니다

증상 빌드는 성공했는데 주소를 열면 404가 뜹니다.

원인 Pages의 브랜치가 main 으로 되어 있습니다. 포크한 룰렛은 빌드 결과가 gh-pages 브랜치에 쌓입니다.

해결 Settings의 Pages에서 Branch를 gh-pages 로 바꾸고 저장합니다.

액션이 빨간 엑스로 끝나고 gh-pages 브랜치가 생기지 않습니다

증상 빌드는 되는데 마지막 배포 단계에서 권한 오류가 납니다.

원인 액션이 내 저장소에 쓸 권한을 못 받았습니다.

해결 Settings의 Actions 안 General로 들어가 Workflow permissions를 읽고 쓰기로 바꾼 뒤, Actions 탭에서 다시 실행합니다.

화면이 하얗게만 나옵니다

증상 주소는 열리는데 아무것도 보이지 않습니다.

원인 포크할 때 저장소 이름을 바꿨습니다. 빌드 설정이 roulette 이라는 이름을 경로로 쓰고 있어 파일을 못 찾습니다.

해결 저장소 이름을 roulette 로 되돌리고 액션을 다시 실행합니다.
