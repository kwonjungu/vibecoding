STEP 05

서버 체험 — 게임과 기록표

게임을 만들어 점수를 서버에 올립니다. 링크만 보내면 다른 기기에서 같은 순위표를 보고, 내가 점수를 올리면 상대 화면이 새로고침 없이 바뀝니다. 학급 대항 순위표를 수업에 그대로 띄울 수 있습니다.

왜 필요한가

4칸에서 앱에 주소가 생겼습니다. 그런데 지금 앱이 기억하는 곳은 브라우저 안 저장 공간(localStorage)뿐이라 점수가 각자 기기에만 남습니다. 이번 칸에서 주방을 짓습니다. 실시간과 동시 접속이 붙어, 누가 점수를 올리면 30명의 순위표가 같은 순간에 바뀝니다.

이번에는 콘솔에 들어가 설정을 손으로 만지지 않습니다. AI Studio Build에게 말로 붙여 달라고 하면 연결과 익명 로그인, 규칙 파일까지 대화로 만들어집니다.

이렇게 합니다

  1. AI Studio의 Build에서 점수가 남는 게임을 만듭니다. 낚시 게임을 예로 듭니다. 그림과 소리는 3칸에서처럼 이미지 생성으로 한꺼번에 뽑아 넣습니다.
  2. 같은 채팅 칸에 아래 프롬프트를 넣습니다. Build가 Firebase 연결과 익명 로그인, firestore.rules, 실시간 갱신 코드까지 만듭니다.
  3. Firebase 설정 팝업이 뜨면 약관에 동의합니다. 이때 프로젝트가 자동으로 만들어집니다.
  4. 배포하고 링크를 공유합니다.

복붙 프롬프트

기록을 기록표로 보여줘.
로그인은 불특정 다수가 그냥 들어오면 되게 해줘.
파이어베이스 붙여줘

순위표에 무엇이 보일지까지 정해 주면 화면이 한 번에 정리됩니다. 위 문장에 이어서 넣습니다.

순위표에는 별명과 점수, 달성 시각 세 가지만 보여줘.
점수가 높은 순으로 열 줄까지 띄워줘.
새 기록이 들어오면 새로고침 없이 바로 바뀌게 해줘.

이러면 성공입니다

  • 링크를 다른 기기에서 열면 같은 순위표가 보입니다.
  • 내가 점수를 올리면 상대 화면의 순위표가 새로고침 없이 바뀝니다.
  • Firebase 콘솔의 사용자 탭에 (익명) 줄이 쌓입니다.

막히면

auth/admin-restricted-operation 이라는 빨간 글씨가 뜹니다

증상 게임은 열리는데 점수를 올리는 순간 화면이 멈추고 auth/admin-restricted-operation 이 뜹니다.

원인 Firebase 콘솔에서 익명 로그인을 아직 사용 설정하지 않았습니다.

해결 콘솔에서 익명을 켭니다. 아래 네 장면을 순서대로 따라갑니다.

익명 로그인을 켜는 네 단계
순서캡처보는 것
① Firebase 콘솔 홈 프로젝트 목록에 Default Gemini Project가 이미 있습니다. AI Studio Build가 만들어 둔 것이므로 새로 만들 필요가 없습니다.
② 왼쪽 메뉴 제품 카테고리를 펼치고 보안을 고른 다음 Authentication을 누릅니다.
③ 로그인 방법 탭 제공업체 목록에서 익명이 사용 설정됨으로 바뀌어 있어야 합니다.
④ 사용자 탭 접속자가 익명으로 쌓입니다. 학생 한 명이 들어올 때마다 한 줄씩 늘어나면 성공입니다.
한 판 했는데 기록이 안 올라옵니다

증상 게임은 끝까지 되는데 순위표가 비어 있고 오류 문구도 없습니다.

원인 firestore.rules 가 서버에 배포되지 않았습니다. 배포 전에는 읽기와 쓰기가 기본으로 막힙니다.

해결 Build에 규칙을 배포해 달라고 하거나 Firebase 콘솔의 Firestore 규칙 탭에서 게시를 누릅니다.

익명을 켜기 전에 열어 둔 탭에서만 안 됩니다

증상 다른 사람 화면에는 점수가 올라가는데 내 탭에서만 기록이 남지 않습니다.

원인 익명을 켜기 전에 열어 둔 탭이라 인증 객체가 null 로 남았습니다.

해결 그 탭에서 F5로 새로고침하면 인증을 다시 받습니다.

AI가 다 해 줘도 콘솔에서 사람이 눌러야 하는 스위치가 남습니다. 빨간 글씨는 요약하지 말고 그대로 복사해 AI에게 붙여넣습니다.

STEP 06

서버 활용 — 날짜별 사진 캘린더

월 달력의 날짜 칸을 누르면 사진 한 장을 올립니다. 하루 한 장만 들어가고 모두가 같은 캘린더를 봅니다. 학급 일기와 급식 기록, 학년 행사 사진첩으로 바로 씁니다.

왜 필요한가

5칸에서 서버에 올린 것은 점수 한 줄이었고 이번에는 사진 한 장입니다. 무거운 만큼 하루 한 장이라는 제한과 사진 규격을 먼저 정해야 앱이 무너지지 않습니다.

무료 조건이 설계를 결정합니다. 사진을 통째로 맡아 주는 Firebase Cloud Storage는 2026년 2월 3일부터 결제 계정이 있어야 만들 수 있습니다. 그래서 브라우저 안에서 정사각형 512픽셀 JPEG, 품질 0.7로 줄인 뒤 문자열로 바꿔 Firestore 문서에 저장합니다. 문서 하나의 한도는 1MB, 줄인 사진은 60KB에서 110KB이므로 여유가 충분합니다.

이렇게 합니다

  1. 만들 것을 한 줄로 적습니다. 월 달력의 날짜 칸을 누르면 사진을 올리고, 하루 한 장만 들어가며, 모두가 같은 캘린더를 봅니다.
  2. 5칸에서 만든 Firebase 프로젝트를 그대로 씁니다. 익명 로그인은 이미 켜져 있습니다.
  3. 아래 프롬프트를 넣습니다. 규격 네 가지를 문장에 못 박지 않으면 AI는 원본 사진을 그대로 올리는 코드를 씁니다.
  4. 배포하고 링크를 공유합니다. 나눠 주기 전에 얼굴이 나온 사진은 올리지 않는다고 약속합니다.

복붙 프롬프트

월 달력 화면을 만들어 줘.
날짜 칸을 누르면 사진을 한 장 올릴 수 있게 해줘.

조건 네 가지를 꼭 지켜줘.
1. 한 날짜에는 사진 한 장만 저장한다. 이미 있으면 바꿀지 먼저 물어본다.
2. 올리기 전에 브라우저에서 정사각형 512픽셀 JPEG로 줄이고 품질은 0.7로 한다.
3. Cloud Storage를 쓰지 말고 줄인 사진을 문자열로 바꿔 Firestore 문서에 저장한다.
4. 얼굴이 나온 사진은 올리지 않는다는 안내 문구를 업로드 칸 위에 항상 보이게 띄운다.

파이어베이스는 이미 붙어 있는 프로젝트를 그대로 써줘.

이러면 성공입니다

  • 같은 날짜에 두 번째 사진을 올리면 바꿀지 묻거나 아예 막습니다.
  • 다른 기기에서 링크를 열어도 같은 사진이 보입니다.
  • 사진이 모두 정사각형으로 보이고 달력 칸 크기가 들쭉날쭉하지 않습니다.

막히면

사진이 안 올라갑니다

증상 파일을 고르면 잠시 멈췄다가 아무 일도 없거나 저장에 실패했다는 문구가 뜹니다.

원인 사진 줄이기를 건너뛰고 원본을 올려 문서 한도 1MB를 넘겼습니다.

해결 올리기 전에 512픽셀로 줄이는 단계를 넣어 달라고 다시 말합니다.

화질이 너무 나쁩니다

증상 달력에 올린 사진이 뭉개져 보이고 글씨가 찍힌 사진은 읽기 어렵습니다.

원인 512픽셀과 품질 0.7이 무료 조건 안에서 쓸 수 있는 상한입니다.

해결 더 키우면 문서 한도에 걸려 저장이 통째로 실패합니다. 가까이에서 밝게 찍고 글씨가 든 장면은 피합니다.

얼굴이 찍힌 사진이 올라갔습니다

증상 학생 얼굴이 나온 사진이 캘린더에 올라와 있습니다.

원인 링크만 있으면 누구나 들어오는 공개 앱이라 얼굴 사진은 처음부터 올리면 안 되는 자료입니다.

해결 그 사진을 지우고 규칙을 다시 안내한 뒤 필요하면 링크를 새로 만듭니다.

STEP 07

앱이 AI를 부르게

이번에는 앱이 스스로 AI에게 묻습니다. 학생이 힌트 버튼을 누르면 앱이 대신 물어 한 문장을 받아 옵니다. 열쇠를 안전한 곳에 두는 방법이 이 칸의 전부입니다.

왜 필요한가

앱이 AI에게 물으려면 열쇠, 곧 API 키가 필요합니다. 이 키를 앱 파일에 적어 두면 화면에 안 보여도 주소를 아는 사람은 누구나 꺼내 갑니다. 남이 쓴 만큼 내 한도가 줄고 요금이 붙기도 합니다. 그래서 열쇠는 주방이 보관하고 앱은 질문만 넘깁니다.

AI Studio Build로 만든 앱은 이 구조를 이미 갖췄습니다. Gemini를 쓰는 앱을 만들면 AI Studio가 키를 서버 쪽 비밀값으로 넣어 두고 호출은 서버가 대신 보냅니다. 키는 학생 화면으로 내려가지 않습니다.

앱을 ZIP으로 내려받아 다른 곳에 올리면 키를 숨기는 일은 다시 내 몫이 됩니다. 그 서버의 환경변수에 GEMINI_API_KEY 를 직접 넣습니다. 도구가 대신 해 주는 일과 내가 책임질 일을 구분하는 것이 이 칸의 내용입니다.

이렇게 합니다

  1. 5칸과 6칸에서 쓰던 AI Studio Build 프로젝트를 그대로 엽니다.
  2. 아래 프롬프트로 힌트 버튼을 붙입니다. 키는 AI Studio가 서버 쪽 비밀값으로 넣어 두므로 따로 발급받아 붙여넣을 것이 없습니다.
  3. AI Studio의 비밀값 패널에서 키가 들어 있는지 눈으로 확인합니다. 이 화면은 캡처하지 않습니다.
  4. 배포하고 힌트 버튼을 눌러 본 뒤, 페이지 소스를 열어 키 문자열이 없는지 확인합니다.

모델은 둘 중에서 고릅니다. 무료로 쓸 수 있는 횟수가 다릅니다.

무료로 쓸 수 있는 횟수
모델분당하루쓰임
gemini-2.5-flash 10회 250회 답이 길고 꼼꼼합니다. 교사가 자료를 만들 때 씁니다.
gemini-2.5-flash-lite 15회 1,000회 짧은 힌트에 알맞습니다. 우리 반 앱은 이쪽으로 충분합니다.

25명이 한 수업에서 세 번씩 눌러도 75회로, flash-lite의 하루 1,000회 안에 넉넉히 들어갑니다.

복붙 프롬프트

문제 화면에 힌트 버튼을 하나 붙여줘.

구조는 이렇게 해줘.
1. 앱은 API 키를 갖지 않는다. 코드 어디에도 키 문자열을 적지 않는다.
2. 앱은 지금 문제를 질문으로 만들어 서버에 보내기만 한다.
   주문서는 {action:"ai", question} 형태로 한다.
3. 서버가 키를 갖고 있고 서버가 Gemini를 부른다.
   모델은 gemini-2.5-flash-lite 를 쓴다.
4. 돌아온 답은 한 문장으로 줄여서 버튼 아래에 띄운다.
   정답은 말하지 말고 어디를 다시 보라고만 알려준다.

이러면 성공입니다

  • 힌트 버튼을 누르면 몇 초 안에 한 문장이 돌아옵니다.
  • 앱 파일을 위에서 아래까지 훑어도 키 문자열이 없습니다.
  • 페이지 소스를 열어 찾아봐도 키 문자열이 나오지 않습니다.

막히면

키를 어디에 넣어야 하는지 모르겠습니다

증상 발급받은 키를 붙여넣을 칸을 찾지 못합니다.

원인 AI Studio Build에서는 붙여넣을 칸이 없는 것이 정상입니다. 키는 도구가 넣어 둡니다.

해결 비밀값 패널에 키가 있는지만 확인합니다. ZIP으로 내려받아 다른 곳에 올릴 때만 그 서버의 환경변수에 GEMINI_API_KEY 를 넣습니다.

하루 한도를 넘겼다는 답이 옵니다

증상 수업 후반부터 힌트가 돌아오지 않고 한도를 넘겼다는 문구가 보입니다.

원인 무료 횟수는 한 학급이 한 수업에서 쓰는 것을 기준으로 잡혀 있습니다. 여러 학급이 같은 키를 하루에 몰아 쓰면 걸립니다.

해결 모델을 gemini-2.5-flash-lite 로 바꾸면 하루 1,000회까지 늘어납니다. 버튼을 연달아 못 누르게 막으면 더 안전합니다.

키가 새어 나간 것 같습니다

증상 키를 캡처에 넣었거나 코드에 붙였다가 지웠습니다. 쓴 적 없는 사용량이 올라가 있습니다.

원인 한 번 밖으로 나간 키는 지워도 저장소 기록과 캡처 파일에 남습니다.

해결 그 키를 즉시 삭제하고 새로 발급받습니다. 키는 공유와 캡처, 코드 삽입이 모두 금지입니다. 있어야 할 곳은 서버 쪽 비밀값 한 곳뿐입니다.
