STEP 05

서버 체험 — 게임과 기록표

게임을 만들어 점수를 서버에 올립니다. 링크만 보내면 다른 기기에서 같은 순위표를 보고, 내가 점수를 올리면 상대 화면이 새로고침 없이 바뀝니다. 학급 대항 순위표를 수업에 그대로 띄울 수 있습니다.

왜 필요한가

4칸에서 앱에 주소가 생겼습니다. 그런데 지금 앱이 기억하는 곳은 브라우저 안 저장 공간(localStorage)뿐이라 점수가 각자 기기에만 남습니다. 이번 칸에서 주방을 짓습니다. 실시간과 동시 접속이 붙어, 누가 점수를 올리면 30명의 순위표가 같은 순간에 바뀝니다.

이번에는 프로젝트와 규칙을 콘솔에서 직접 만들지 않습니다. AI Studio Build에게 말로 붙여 달라고 하면 연결과 익명 로그인, 규칙 파일까지 대화로 만들어집니다.

이렇게 합니다

  1. AI Studio의 Build에서 점수가 남는 게임을 만듭니다. 낚시 게임을 예로 듭니다. 그림과 소리는 3칸에서처럼 이미지 생성으로 한꺼번에 뽑아 넣습니다.
  2. 같은 채팅 칸에 아래 프롬프트를 넣습니다. Build가 Firebase 연결과 익명 로그인, firestore.rules, 실시간 갱신 코드까지 만듭니다.
  3. Firebase 설정 팝업이 뜨면 약관에 동의합니다. 이때 프로젝트가 자동으로 만들어집니다.
  4. 배포하고 링크를 공유합니다.

서버 연결하는 법

여기까지 오면 화면은 뜨는데 점수가 안 올라갑니다. 콘솔에서 익명 로그인을 켜야 합니다. AI가 대신 못 누르는 스위치 하나입니다.

먼저 아래 프롬프트를 Build에 넣습니다. 규칙 배포와 인증 처리는 AI가 하고, 콘솔에서 사람이 누를 것만 남습니다.

서버 연결을 마무리해 줘.

1. 익명 로그인이 아직 안 켜져 있어도 앱이 멈추지 않게 해줘.
   인증을 못 받으면 오류 대신 안내 문구를 보여 주고, 켠 뒤 새로고침하면 바로 이어지게 해줘.
2. firestore.rules 를 서버에 배포해 줘. 파일만 있고 배포가 안 되면 읽기와 쓰기가 막혀.
   순위표는 누구나 읽을 수 있고, 점수는 접속한 사람이 자기 기록만 올리게 해줘.
3. 점수를 올릴 때 인증이 아직 안 됐으면 먼저 익명 인증을 받은 다음 올려 줘.
4. 내가 Firebase 콘솔에서 직접 눌러야 하는 것이 있으면
   어느 메뉴를 어떤 순서로 누르는지 알려 줘.

그다음 콘솔에서 익명 로그인을 켭니다.

익명 로그인을 켜는 네 단계
순서캡처보는 것
① Firebase 콘솔 홈 프로젝트 목록에 Default Gemini Project가 이미 있습니다. AI Studio Build가 만들어 둔 것이므로 새로 만들 필요가 없습니다.
② 왼쪽 메뉴 제품 카테고리를 펼치고 보안을 고른 다음 Authentication을 누릅니다.
③ 로그인 방법 탭 제공업체 목록에서 익명이 사용 설정됨으로 바뀌어 있어야 합니다.
④ 사용자 탭 접속자가 익명으로 쌓입니다. 학생 한 명이 들어올 때마다 한 줄씩 늘어나면 성공입니다.

복붙 프롬프트

기록을 기록표로 보여줘.
로그인은 불특정 다수가 그냥 들어오면 되게 해줘.
파이어베이스 붙여줘

순위표에 무엇이 보일지까지 정해 주면 화면이 한 번에 정리됩니다. 위 문장에 이어서 넣습니다.

순위표에는 별명과 점수, 달성 시각 세 가지만 보여줘.
점수가 높은 순으로 열 줄까지 띄워줘.
새 기록이 들어오면 새로고침 없이 바로 바뀌게 해줘.

이러면 성공입니다

  • 링크를 다른 기기에서 열면 같은 순위표가 보입니다.
  • 내가 점수를 올리면 상대 화면의 순위표가 새로고침 없이 바뀝니다.
  • Firebase 콘솔의 사용자 탭에 (익명) 줄이 쌓입니다.

막히면

auth/admin-restricted-operation 이라는 빨간 글씨가 뜹니다

증상 게임은 열리는데 점수를 올리는 순간 화면이 멈추고 auth/admin-restricted-operation 이 뜹니다.

원인 Firebase 콘솔에서 익명 로그인을 아직 사용 설정하지 않았습니다.

해결 위 익명 로그인 네 단계를 건너뛰었습니다. 그대로 따라 하면 풀립니다.

한 판 했는데 기록이 안 올라옵니다

증상 게임은 끝까지 되는데 순위표가 비어 있고 오류 문구도 없습니다.

원인 firestore.rules 가 서버에 배포되지 않았습니다. 배포 전에는 읽기와 쓰기가 기본으로 막힙니다.

해결 Build에 규칙을 배포해 달라고 하거나 Firebase 콘솔의 Firestore 규칙 탭에서 게시를 누릅니다.

익명을 켜기 전에 열어 둔 탭에서만 안 됩니다

증상 다른 사람 화면에는 점수가 올라가는데 내 탭에서만 기록이 남지 않습니다.

원인 익명을 켜기 전에 열어 둔 탭이라 인증 객체가 null 로 남았습니다.

해결 그 탭에서 F5로 새로고침하면 인증을 다시 받습니다.

빨간 글씨는 요약하지 말고 그대로 복사해 AI에게 붙여넣습니다.

STEP 06

한 걸음 더 코딩 — 우리 반 사진 캘린더

여기부터는 단계를 일러 주지 않습니다. 미션과 지켜야 할 조건만 드립니다. 나머지는 스스로 풉니다.

왜 미션인가

5칸까지 오면서 만드는 법은 익혔습니다. 남은 것은 조건을 지키며 끝까지 가는 일입니다. 그건 따라 해서는 늘지 않습니다.

조건이 곧 설계입니다. 무료 범위와 개인정보가 무엇을 만들 수 있는지를 먼저 정합니다.

미션

우리 반이 함께 쓰는 달력을 만듭니다. 날짜를 누르면 사진 한 장이 올라가고, 다른 기기에서 열어도 같은 사진이 보입니다.

지켜야 할 조건

  1. 하루에 한 장만 남깁니다. 이미 있으면 바꿀지 먼저 묻습니다.
  2. 올리기 전에 정사각형 512픽셀 JPEG, 품질 0.7로 줄입니다.
  3. Firebase Cloud Storage를 쓰지 않습니다. 2026년 2월 3일부터 결제 계정이 있어야 만들 수 있습니다. 줄인 사진을 문자열로 바꿔 Firestore 문서에 넣습니다.
  4. 얼굴이 나온 사진은 올리지 않는다는 안내를 업로드 칸 위에 늘 띄웁니다.
막히면 여는 힌트

조건 네 가지를 프롬프트 문장에 그대로 넣지 않으면 AI는 원본 사진을 올리는 코드를 씁니다.

문서 하나의 한도는 1MB입니다. 512픽셀로 줄인 사진은 60KB에서 110KB입니다.

5칸에서 쓰던 Firebase 프로젝트를 그대로 씁니다. 익명 로그인은 이미 켜져 있습니다.

한 걸음 더 — 진짜 서버를 내 손으로

5칸의 Firebase는 AI가 붙여 주었습니다. 이번에는 내가 붙입니다. 같은 캘린더를 Supabase로 옮깁니다.

  1. supabase.com에서 프로젝트를 만듭니다. 카드가 필요 없습니다.
  2. Table Editor에서 photos 테이블을 만듭니다. 열은 day와 image, created_at 입니다.
  3. Settings의 API에서 Project URL과 anon public 키를 복사합니다.
  4. 아래 프롬프트로 앱을 연결합니다.
  5. 테이블에 RLS를 켜고 정책을 만듭니다. 켜지 않으면 링크를 아는 누구나 남의 사진을 지울 수 있습니다.

여기까지 Supabase로 옮긴 캘린더가 7칸의 출발점입니다.

Gemini를 코치로 두는 마스터 프롬프트

Build는 만드는 곳이고 Gemini는 옆에서 확인해 주는 사람입니다. 아래를 Gemini에 붙여넣고 한 단계씩 따라갑니다.

너는 초등학교 선생님이 앱 만들기 미션을 끝까지 해내도록 옆에서 돕는 코치야.
선생님은 코딩을 몰라. 실제 작업은 Google AI Studio의 Build 화면에서 해.
너는 대신 만들어 주는 사람이 아니라 한 단계씩 확인해 주는 사람이야.

[미션]
우리 반이 함께 쓰는 사진 캘린더를 만든다.
날짜를 누르면 사진 한 장이 올라가고, 다른 기기에서 열어도 같은 사진이 보인다.

[반드시 지킬 조건]
1. 하루에 한 장만 남긴다. 이미 있으면 바꿀지 먼저 묻는다.
2. 올리기 전에 정사각형 512픽셀 JPEG, 품질 0.7로 줄인다.
3. Firebase Cloud Storage를 쓰지 않는다. 줄인 사진을 문자열로 바꿔 Firestore 문서에 넣는다.
4. 얼굴이 나온 사진은 올리지 않는다는 안내를 업로드 칸 위에 늘 띄운다.

[진행 방식]
- 전체를 여섯 단계로 나누고, 시작할 때 단계 목록만 먼저 보여 줘.
- 그다음부터는 한 번에 한 단계씩만 안내해.
- 한 단계는 이렇게 써. 첫째 지금 할 일 한 문장. 둘째 어디를 눌러야 하는지.
  셋째 Build에 붙여넣을 문장이 있으면 그 문장.
- 단계 끝에 눈으로 확인할 수 있는 것 한 가지를 물어봐.
- 내가 됐어요 라고 하면 다음 단계로 가. 안 돼요 라고 하면
  원인을 두 가지만 추측해서 무엇을 확인할지 물어봐.
- 답변 맨 위에 3/6 처럼 지금 몇 번째인지 표시해.

[하지 말 것]
- 한 번에 전체 코드를 쏟아내지 마. 내가 코드를 달라고 할 때만 줘.
- 한 단계 안내는 다섯 줄을 넘기지 마.
- 내가 확인했다고 말하기 전에 다음 단계로 넘어가지 마.
- 조건 네 가지 중 하나라도 빠진 채로 진행하지 마.

준비됐으면 여섯 단계 목록부터 보여 주고 시작하자.
Gemini 열기

출발 프롬프트

월 달력 화면을 만들어 줘.
날짜 칸을 누르면 사진을 한 장 올릴 수 있게 해줘.
조건 네 가지를 꼭 지켜줘.
1. 한 날짜에는 사진 한 장만 저장한다. 이미 있으면 바꿀지 먼저 물어본다.
2. 올리기 전에 브라우저에서 정사각형 512픽셀 JPEG로 줄이고 품질은 0.7로 한다.
3. Cloud Storage를 쓰지 말고 줄인 사진을 문자열로 바꿔 Firestore 문서에 저장한다.
4. 얼굴이 나온 사진은 올리지 않는다는 안내 문구를 업로드 칸 위에 항상 보이게 띄운다.
파이어베이스는 이미 붙어 있는 프로젝트를 그대로 써줘.

Supabase 연결 프롬프트

이 앱의 저장소를 Supabase로 바꿔 줘.

1. supabase-js는 CDN으로 불러온다. 빌드 도구는 쓰지 않는다.
2. 연결 정보는 코드 맨 위 한 곳에 모아 준다.
   const SUPABASE_URL = "[프로젝트 URL]";
   const SUPABASE_ANON_KEY = "[anon public 키]";
3. photos 테이블을 쓴다. 열은 day(날짜, 고유값), image(문자열), created_at(시각)이다.
4. 사진은 올리기 전에 정사각형 512픽셀 JPEG 품질 0.7로 줄여 문자열로 저장한다.
5. 같은 날짜에 이미 사진이 있으면 덮어쓸지 먼저 묻는다.
6. 다른 사람이 올린 사진도 새로고침 없이 보이도록 실시간 구독을 붙인다.

anon 키는 공개되는 값이야. 그래서 테이블에 RLS를 켜야 해.
읽기는 모두 허용하고 쓰기는 하루 한 장만 되도록 막는 SQL도 함께 줘.
그 SQL을 Supabase의 SQL Editor에 어떻게 붙여넣는지도 한 줄로 알려 줘.

스스로 확인

  • 같은 날짜에 두 번 올리면 바꿀지 묻습니다.
  • 다른 기기에서 열어도 같은 사진이 보입니다.
  • 사진이 모두 정사각형이라 달력 칸이 들쭉날쭉하지 않습니다.

막히면

사진이 안 올라갑니다

증상 파일을 고르면 멈췄다가 저장에 실패했다는 문구가 뜹니다.

원인 줄이기를 건너뛰고 원본을 올려 문서 한도 1MB를 넘겼습니다.

해결 512픽셀로 줄이는 단계를 넣어 달라고 다시 말합니다.

화질이 너무 나쁩니다

증상 사진이 뭉개지고 글씨가 찍힌 장면은 읽기 어렵습니다.

원인 512픽셀과 품질 0.7이 무료 조건 안의 상한입니다.

해결 더 키우면 저장이 통째로 실패합니다. 가까이에서 밝게 찍습니다.

남이 올린 사진이 지워집니다

증상 Supabase로 옮긴 뒤 아무나 사진을 지울 수 있습니다.

원인 RLS를 켜지 않았습니다. anon 키는 공개되는 값이라 키만으로는 아무것도 막지 못합니다.

해결 테이블에 RLS를 켜고 쓰기 정책을 만듭니다.

방학이 지나니 앱이 멈춰 있습니다

증상 잘 되던 캘린더가 오류만 냅니다.

원인 Supabase 무료 프로젝트는 이레 동안 아무도 쓰지 않으면 잠깁니다.

해결 대시보드에서 다시 켭니다. 개학 전에 미리 열어 둡니다.

STEP 07

한 걸음 더 코딩 — 나만의 캘린더에 AI 붙이기

6칸의 캘린더에 정리 어시스턴트를 붙입니다. 생각나는 대로 적어 넣으면 캘린더에 넣을 내용으로 정리해 줍니다. 바깥 인공지능을 불러오는 문과 그 문을 여는 열쇠를 다루는 칸입니다.

왜 필요한가

1칸에서 API를 홀과 주방 사이 주문서라고 했습니다. 주문서는 바깥으로도 나갑니다. 우리 주방이 못 만드는 것은 다른 집에 주문합니다. 인공지능도 번역도 지도도 그렇게 데려옵니다.

열쇠는 그 집이 나를 알아보는 표입니다. 내 이름으로 문이 열리니 남이 주우면 내 이름으로 씁니다. 그런데 브라우저에서 도는 것은 전부 공개입니다. 환경변수에 넣는 것만으로는 숨겨지지 않습니다. 열쇠를 쓰는 코드가 서버에서 돌아야 합니다.

미션

캘린더에 정리 어시스턴트를 붙입니다. 칸 하나에 생각나는 대로 적습니다. 0924 3 미팅 처럼 짧게 적어도 되고 문장으로 적어도 됩니다. 어시스턴트가 날짜와 제목과 기록으로 갈라 캘린더에 넣을 모양으로 돌려줍니다. 메모를 옮겨 적는 일이 사라집니다.

서버 함수 하나가 열쇠 두 개를 맡습니다. 하나는 AI를 부르는 열쇠, 하나는 우리 반 데이터를 다루는 열쇠입니다. 6칸에서는 브라우저가 직접 Supabase를 불러 공개되는 anon 키를 RLS로 막았습니다. 이제 서버가 부르니 서버 전용 키를 쓰고, 브라우저는 데이터에 직접 닿지 않습니다.

지켜야 할 조건

  1. 열쇠는 모두 Vercel 환경변수에 넣습니다. 이름 앞에 VITE_ 나 NEXT_PUBLIC_ 을 붙이지 않습니다. 붙이면 브라우저 파일에 박힙니다.
  2. 열쇠를 쓰는 코드는 api 폴더의 서버 함수에 둡니다. 앱은 그 함수에 부탁만 보냅니다.
  3. Supabase는 anon 키가 아니라 서버 전용 키를 씁니다. RLS를 무시하는 키라 브라우저로 절대 내보내지 않습니다.
  4. 어시스턴트가 정리한 것은 제안일 뿐입니다. 저장하기 전에 선생님이 고칠 수 있고, 고친 것이 저장됩니다.
  5. 환경변수를 넣은 뒤에는 다시 배포해야 반영됩니다.

거치는 곳

  1. 6칸에서 Supabase로 옮긴 캘린더를 AI Studio Build에서 엽니다. console.groq.com 에서 내 열쇠를 하나 발급받아 둡니다.
  2. GitHub 탭에서 저장소로 싱크합니다. 4칸의 길 B와 같습니다.
  3. vercel.com에서 그 저장소를 가져와 배포합니다.
  4. Settings의 Environment Variables에 열쇠 둘과 주소 하나를 넣습니다. GROQ_API_KEY, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY 입니다. 뒤 두 개는 Supabase의 Settings 안 API에서 가져옵니다.
  5. 다시 배포합니다.
  6. 페이지 소스에서 열쇠를 검색해 아무것도 안 나오는지 확인합니다.

마지막 미션 — 우리 반 번역 보드

여덟 칸에서 배운 것을 한 앱에 모읍니다. 붙임쪽지를 주제별로 붙이는 보드인데, 글을 올리면 여러 나라 말로 함께 보입니다. 한국어가 아직 서툰 친구가 같은 화면에서 같이 읽습니다.

  • 주제 칸을 만듭니다. 자기소개, 오늘의 이야기, 칭찬해요처럼 반에 필요한 칸입니다.
  • 카드를 붙이면 서버에 저장되고 모두의 화면에 나타납니다.
  • 번역 버튼을 누르면 원문 아래에 여러 나라 말이 함께 펼쳐집니다.
  • 이름은 별명으로 적고 얼굴 사진 대신 귀여운 동물 그림을 씁니다.
  • 열쇠는 전부 서버에 둡니다. 화면 어디에도 나오지 않습니다.

원문을 지우고 번역만 남기지 않습니다. 쓴 사람의 말이 먼저 보이고 번역이 그 아래에 붙습니다. 번역은 도와주는 것이지 대신하는 것이 아닙니다.

우리 반 번역 보드를 만들어 줘. 붙임쪽지를 붙이는 보드야.

[화면]
1. 주제 칸을 세로로 늘어놓는다. 칸 제목은 선생님이 정한다.
2. 칸마다 여기에 추가 버튼이 있다. 누르면 별명과 글을 적어 카드를 붙인다.
3. 카드에는 별명, 동물 그림, 글, 번역 버튼, 좋아요 버튼이 있다.

[번역]
4. 번역 버튼을 누르면 원문 아래에 여러 나라 말을 펼친다.
   원문은 지우지 않는다. 처음에는 접어 두고 버튼으로 펼친다.
5. 어느 말로 번역할지는 선생님이 설정에서 고른다. 우리 반에 필요한 말만 고른다.
6. 번역은 서버 함수가 Groq에게 부탁한다.
   주소는 https://api.groq.com/openai/v1/chat/completions 이고
   모델은 llama-3.1-8b-instant 를 쓴다.
   초등학생이 읽는 쉬운 문장으로 옮겨 달라고 부탁한다.

[저장]
7. 카드와 번역은 Supabase에 저장한다. 번역은 한 번 해 두고 다시 부르지 않는다.
8. 다른 사람이 붙인 카드도 새로고침 없이 나타나게 실시간 구독을 붙인다.

[안전]
9. 열쇠는 Vercel 환경변수에 두고 서버 함수에서만 쓴다.
   GROQ_API_KEY, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY 세 개다.
   이름 앞에 VITE_ 나 NEXT_PUBLIC_ 을 붙이지 마.
10. 실명과 얼굴 사진은 받지 않는다. 별명과 동물 그림만 쓴다.

동물 그림은 3칸에서 한 대로 한꺼번에 뽑습니다. 스타일 접두어를 매번 똑같이 붙이고 한 장에 2×2로 받으면 넷이 한 식구처럼 보입니다.

둥글둥글하고 귀여운 동물 얼굴 아이콘을 만들어 줘.
한 장에 2×2로 네 마리를 넣어 줘. 펭귄, 여우, 토끼, 강아지야.
납작한 벡터 그림이고 선은 굵게, 색은 밝고 부드럽게.
