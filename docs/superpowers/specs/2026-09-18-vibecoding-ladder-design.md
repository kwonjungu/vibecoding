# 바이브코딩 사다리 — 설계 문서

작성일 2026-09-18 · 저장소 `kwonjungu/vibecoding` · 배포 예정 `https://kwonjungu.github.io/vibecoding/`

## 1. 배경과 문제

평택교육지원청 초등 AI 디지털 전문가 아카데미 연수 「바이브코딩 심화편」(3·4교시, 15:00~16:50)을 구글 슬라이드 74장으로 설계해 두었다. 두 가지 문제가 확인되었다.

- **내용 수준**: 식당 비유 → AI Studio 이사 → assets → Apps Script + 시트 → 학급코드 연동 → GitHub Pages를 100분에 밀어 넣어, 비전공 교사 30명 기준으로 과하다.
- **전달 매체**: 74장을 순서대로 넘기는 방식이라 출발점이 다른 참가자가 중간에 이탈하면 복귀할 수 없다.

## 2. 해결 방향

한 줄로 늘어선 100분 대신 **8칸 사다리**로 재구성하고, 매체를 슬라이드에서 **정적 웹 페이지**로 옮긴다.

- 각 칸은 독립적으로 완결된다. 어느 칸에서 멈춰도 "여기까지만 해도 수업에 쓸 수 있다"가 성립한다.
- 참가자는 자기 위치를 스스로 확인하고 이탈 지점에서 복귀할 수 있다.
- 연수 100분에는 0~5칸을 함께 오르고, 6~7칸은 페이지에 남겨 사후에 잇는다.

형태는 기존 저장소 `kwonjungu/classroomaicontents`의 디자인 시스템과 마크업 패턴을 승계한다.

### 칸별 내용

**0. 준비물 챙기기**
계정 3개를 각각 카드로 제시한다. 카드마다 로고 · 가입 버튼 · 주의사항 한 줄.
- GitHub — 사용자명은 영문 소문자·숫자·하이픈. 주소에 그대로 붙는다.
- Google AI Studio — 개인 Gmail로 로그인. 학교 계정은 막히는 경우가 많다.
- Firebase — 같은 개인 Gmail. 카드 등록 없이 Spark(무료) 그대로 쓴다.

**1. 더 나은 바이브코딩을 위한 배경지식** (개념 칸 — 실습 없음)
네 덩어리로 구성한다.
- *설계 목적 설정*: "무엇을 만들까"가 아니라 "무엇이 불편한가"에서 출발. 만들기 전 한 줄로 적는다 — 누가 · 어디서 · 무엇을 · 몇 분 안에. 예) "4학년 25명이 · 전자칠판 앞에서 · 지도 퀴즈를 · 10분 안에." 이 줄이 프롬프트의 뼈대이자 "이 정도면 됐다"의 기준선이 된다.
- *도구 선택*: Canvas는 홀만 꾸미는 인테리어 앱, AI Studio는 주방 열쇠(API 키)까지 주는 곳, 설치형 도구는 설계·시공·입주를 맡기는 공사업체. 고르는 기준 셋 — 학교 컴퓨터에 설치할 수 있나 · 무료 조건이 무엇인가 · 한도가 잠기면 수업이 멈추나.
- *과정*: 한 번에 완성이 아니라 대화. 크게 한 번 만들고 그 뒤엔 한 번에 하나씩만 고친다. 고치기 전 백업(`index_백업.html`)이 가장 값싼 안전장치. 프롬프트에 넣을 세 가지 — 무엇을 · 어떻게 · 누구를 위해.
- *마인드셋*: (디버깅) 오류는 실패가 아니라 정보다. 빨간 글씨를 그대로 복사해 AI에게 붙여넣는 것이 가장 빠르다. "안 돼요"가 아니라 "어디까지 됐고 무엇을 눌렀을 때 무엇이 나왔는지"를 말한다. 세 번 시도해도 안 되면 백업으로 돌아간다. (개인정보) 학생 이름·얼굴은 공개 저장소에 올리지 않는다. 학생은 회원가입 없이 학급 코드 + 번호로 들어온다. API 키는 코드에 넣지 않고 서버에만 둔다. 교과서 지문·삽화가 든 앱은 교실 안에서만 쓴다. 학급 코드는 수업이 끝나면 바꾼다.

**2. 웹페이지 디자인 — 같은 내용, 다른 인상**
이 칸의 주제는 "만들기"가 아니라 **디자인 바꾸기**다. 바이브코딩 결과물이 전부 비슷하게 생기는 이유는 아무도 디자인을 지시하지 않아 AI의 기본값(보라색 그라데이션·둥근 카드·이모지·가운데 정렬)이 그대로 나오기 때문이다. DESIGN.md를 건네면 그 기본값이 바뀐다.

실습 순서:
1. *만들기(짧게)* — Gemini Canvas에 활동지 프롬프트를 넣어 한 파일 앱(`index.html`)을 만든다. 메모장에 UTF-8로 저장(파일 형식 모든 파일, 이름 `index.html`, `.txt` 아님) 후 더블클릭.
2. *전형적인 결과물 보기* — 저장소의 `demo/worksheet-before.html`(4학년 사회 "우리 지역의 문화유산" 활동지)을 연다. **일부러 전형적으로 만든 표본**이다. 2번을 못 만들었거나 실패한 사람은 이 파일로 3단계부터 바로 이어간다 — 디자인 실습이 만들기에서 막히면 안 된다.
3. *왜 다 비슷한가* — AI의 기본값을 눈으로 확인한다. 보라 그라데이션 배경, 20px 라운드 카드, 짙은 그림자, 제목마다 이모지, 전부 가운데 정렬, `Made with ❤️ by AI`.
4. *DESIGN.md란* — 마크다운 한 장에 색·타이포·간격·컴포넌트 규칙을 담아 AI에게 넘기는 디자인 명세서. 프로젝트에 파일 하나 넣으면 AI가 그 감성으로 UI를 만든다.
5. *고르기* — getdesign.md에서 브랜드 DESIGN.md를 미리보기하고 복사한다(Stripe·Linear·Notion·Vercel 등 70여 종, MIT). 수업용으로는 대비가 뚜렷한 것을 권한다.
6. *다시 만들기* — AI Studio 또는 Canvas에 `활동지 HTML 전체 + DESIGN.md 전문 + "이 디자인 명세에 맞춰 다시 만들어 줘. 내용과 문항은 그대로 두고 보이는 것만 바꿔 줘"`를 넣는다.
7. *비교* — `worksheet-before.html`과 결과물을 두 탭에 나란히 띄운다. 바뀐 것은 색·여백·글꼴·정렬이고, **문항과 정답은 하나도 바뀌지 않았다**는 점을 확인한다.

성공 확인: 두 파일의 문항이 같다 · 보라 그라데이션이 사라졌다 · 이모지 없이도 읽힌다.

**3. 재료 만들어 붙이기 — 그리고 폴더가 되는 순간**

(1) *이사* — Canvas에서 AI Studio로 옮긴다. 여러 파일을 다루는 순간이므로 명분이 자연스럽다. 시스템 지시는 "항상 `index.html` 전체를 코드블록 하나로, 생략 없이".

(2) *재료 생성* — 그림은 이미지 생성(나노바나나 계열)으로 한꺼번에 뽑아 `assets/`에 영문 소문자 파일명으로 넣는다. AI에게는 그림이 아니라 **경로**를 알려 준다. 재료 프롬프트 원칙 4가지: 스타일 접두어 고정 · 배경 단색 · 시리즈는 한 장에 2×2 · 정사각형.

(3) *효과음* — 외부 파일 없이 **코드가 직접 만들게** 한다(Web Audio). 내려받기·파일명·경로 문제가 전부 사라진다.

(4) *Before / After 실물* — 같은 낚시 게임의 두 화면을 나란히 싣는다. `assets/shot/rung3-assets-before.png`는 기본 이모지로만 돌아가는 상태, `assets/shot/rung3-assets-after.png`는 생성한 이미지 스프라이트를 넣은 상태다. 게임 로직은 하나도 바뀌지 않았고 **재료만 바뀌었다**는 점을 짚는다. 2칸(디자인)과 같은 구조의 깨달음이다.

(5) *단일 프로그램에서 폴더 기반 프로젝트 앱으로* — 이 칸의 개념적 핵심이다. 한 파일 앱은 뼈대·재료·규칙이 한 장에 뭉쳐 있어, 커지면 어디를 고쳐야 할지 알 수 없다. 앱이 되려면 **역할이 다른 것들이 폴더에 모여야 한다.**

| 폴더·파일 | 역할 | 식당 비유 |
|---|---|---|
| `index.html` | 들어오는 문. 뼈대 | 출입구 |
| `assets/` | 재료 — 그림·소리 | 홀의 인테리어 |
| `src/App.tsx` | 엔진 — 규칙과 계산이 도는 곳 | 주방의 조리대 |
| `src/components/` | 컴포넌트 — 화면 조각(기록표 창, 도감 창) | 테이블·메뉴판 |
| `src/index.css` | 디자인 규칙 | 인테리어 도면 |
| `firestore.rules` | 누가 읽고 쓸 수 있는지 | 출입 규정 |

낚시 게임의 실제 파일 목록이 그대로 이 표다. "AI가 파일을 여러 개 만들었다"는 것은 실수가 아니라 **앱이 된 증거**다. 이 이해가 4칸의 배포 두 갈래(파일 하나면 GitHub Pages, 폴더면 ai.studio)로 바로 이어진다.

성공 확인: `assets` 폴더에 파일이 3개 있다 · 전부 영문 소문자다 · 더블클릭했을 때 이모지가 아니라 내 그림이 보인다.

**4. 주소 만들기 — 두 갈래를 나란히**
앱의 형태에 따라 배포 방법이 갈린다. 둘 다 알려 주고, 어느 쪽인지 스스로 판단하게 한다.

- *길 A — 파일이 하나(`index.html`)일 때: GitHub Pages.* 저장소 생성(Public, README 체크 안 함) → `index.html`과 `assets` 폴더째 업로드 → Settings › Pages › `main` / `(root)` → `https://[아이디].github.io/[저장소명]/`. 1~3분 대기, Actions 탭 초록 체크 확인. 폴더 통째로 올릴 수 있고, 주소가 내 것이며, 영구적이다.
- *길 B — 파일이 여러 개(AI Studio Build 프로젝트)일 때: ai.studio 주소.* Build 화면에서 바로 배포하고 링크를 공유한다. 6~8칸이 이 길이다.
- 판단 기준 한 줄: **"메모장으로 열 수 있는 파일 하나면 A, AI가 폴더를 만들어 줬으면 B."**
- 플랜 C: Netlify Drop(`app.netlify.com/drop`)에 폴더를 끌어다 놓는다.

**5. 결과 모으기 (쉬운 길)** — 구글 시트 생성 → 확장 프로그램 › Apps Script → 코드 붙여넣기 → 웹 앱으로 배포(실행: 나 / 액세스: 모든 사용자) → `/exec` 주소에서 `{"ok":true}` 확인 → `index.html` 맨 위 `SERVER_URL`에 붙여넣고 학급 코드 입장 + 결과 저장 붙이기. 주문서 양식 `join` / `save`. Apps Script 특성상 반드시 POST · `Content-Type: text/plain;charset=utf-8` · `redirect: "follow"`. 교사 대시보드는 따로 만들지 않는다 — 시트가 이미 대시보드다.

**6. 서버 체험 — 게임과 기록표**
5칸(시트)과의 차이는 **실시간**과 **동시 접속**이다. 콘솔에서 손으로 설정하지 않고, **AI Studio Build에게 말로 붙여 달라고 한다.**

실습 순서:
1. Build에서 게임을 하나 만든다(예: 낚시 게임). 에셋 이미지는 나노바나나 계열 이미지 생성으로 한꺼번에 뽑아 넣는다.
2. `"기록을 기록표로 보여줘. 로그인은 불특정 다수가 그냥 들어오면 되게 해줘. 파이어베이스 붙여줘"` — Build가 Firebase 연결·익명 인증·`firestore.rules`·실시간 리스너까지 만든다.
3. 뜨는 Firebase 설정 팝업에서 약관에 동의한다.
4. 배포하고 링크를 공유한다. **링크만 받아도 다른 사람이 동시에 들어와 같은 순위표를 본다.**

`막히면` 항목 — 실제로 걸린 세 가지를 그대로 싣는다:
- `auth/admin-restricted-operation` → Firebase 콘솔에서 **익명(Anonymous) 로그인을 사용 설정**하지 않았다. 캐프쳐 4장을 순서대로 실는다:

  | 순서 | 캡처 | 보는 것 |
  |---|---|---|
  | ① | `rung6-firebase-01-console.png` | Firebase 콘솔 홈. AI Studio Build가 만들어 둔 **Default Gemini Project**가 이미 목록에 있다 — 프로젝트를 새로 만들 필요가 없다 |
  | ② | `rung6-firebase-02-menu-auth.png` | 왼쪽 메뉴 **제품 카테고리 › 보안 › Authentication** |
  | ③ | `rung6-firebase-03-providers.png` | **로그인 방법** 탭. 제공업체 목록에서 **익명**이 "사용 설정됨"이 되어야 한다 |
  | ④ | `rung6-firebase-04-users.png` | **사용자** 탭. 켜고 나면 접속자가 `(익명)`으로 쌓인다. 여기 줄이 늘어나면 성공이다 |

  ④는 성공 확인 화면이기도 하다. "서버가 사람을 세고 있다"를 눈으로 보여주는 장면이라 5칸의 시트 한 줄과 대응시킨다.
- *한 판 했는데 기록이 안 올라온다* → `firestore.rules`가 **서버에 배포되지 않았다.** 파일만 있고 배포가 안 되면 읽기·쓰기가 기본 차단된다.
- *익명을 켜기 전에 열어 둔 탭* → 인증 객체가 `null`로 남아 로컬에만 저장된다. **새로고침(F5)** 하면 된다.

이 세 가지는 "AI가 다 해 줘도 콘솔에서 사람이 눌러야 하는 스위치가 남는다"는 것을 보여주는 교재다. 실패를 숨기지 않고 1칸(디버깅 마인드셋)과 연결한다.

**7. 서버 활용 — 날짜별 사진 캘린더**
6칸이 "점수 한 줄"이었다면 이번엔 "사진 한 장"이다. 종합 과제.

만들 것: 월 달력 화면에서 날짜 칸을 누르면 사진을 올리고, **하루에 한 장만** 들어가며, 모두가 같은 캘린더를 본다.

**무료 제약이 설계를 결정한다.** Firebase Cloud Storage(파일 업로드)는 2026-02-03부터 버킷 생성에 결제 계정이 필요해 쓸 수 없다. 그래서 사진을 브라우저에서 **정사각형 512px JPEG(품질 0.7)로 줄여 Firestore 문서에 문자열로 저장**한다. 문서 한도 1MB, 줄인 사진은 60~110KB라 여유가 있다. "정해진 규격"이 취향이 아니라 **조건**인 이유를 그대로 가르친다.

프롬프트에 반드시 넣을 것: 날짜당 한 장 제한 · 업로드 전 정사각형 512px 리사이즈 · Storage 대신 Firestore 문자열 저장 · 얼굴 사진 금지 안내 문구.

`막히면`: 사진이 안 올라간다 → 리사이즈를 건너뛰어 1MB를 넘긴 경우다. 원본을 바로 올리지 않았는지 확인한다.

**8. 앱이 AI를 부르게** — AI Studio에서 Gemini API 키 발급 → Apps Script 스크립트 속성 `GEMINI_KEY`에만 저장 → `{action:"ai", question}` 주문서로 힌트 한 문장. 키는 공유·캡처·코드 삽입 모두 금지. 새어 나가면 삭제하고 재발급.

## 10. 확인된 사실 (2026-09 기준)

- Gemini API 무료 등급은 Flash 계열만. `gemini-2.5-flash` 10 RPM / 250 RPD, `gemini-2.5-flash-lite` 15 RPM / 1,000 RPD.
- Firebase Spark(무료)는 결제 수단 없이 Firestore·Hosting·Authentication 사용 가능. Firestore 하루 읽기 50,000 · 쓰기 20,000 · 삭제 20,000, 저장 1GB.
- Cloud Storage for Firebase는 2026-02-03부터 버킷 생성에 결제 계정이 필요하다. **사다리에서 제외한다.**
- Firebase Studio는 2026-06-22부터 신규 가입·워크스페이스 생성이 중단되었고 2027-03-22 지원 종료 예정이다. **연수에서 쓸 수 없다.** 파이어베이스는 콘솔(Firestore) 용도로만 쓴다.
- DESIGN.md는 마크다운 한 장에 디자인 시스템을 담아 AI 에이전트에게 넘기는 포맷이다. getdesign.md와 GitHub `voltagent/awesome-design-md`에 70여 개 브랜드 명세가 MIT로 공개되어 있다.
- AI Studio Build는 대화만으로 Firebase 연결·익명 인증·`firestore.rules` 생성·실시간 리스너까지 붙인다(2026-09 실측). 다만 **콘솔에서 사람이 눌러야 하는 스위치**가 남는다: Authentication의 익명 사용 설정, 그리고 규칙의 서버 배포.
- 배포된 Build 앱은 **링크 공유만으로 동시 접속**이 된다.
- Apps Script `fetch`는 `text/plain` POST + `redirect: "follow"`여야 CORS 오류가 나지 않는다.
