STEP 00

준비물 챙기기

도구는 전부 무료이고 설치할 것이 없습니다. 계정 세 개만 미리 만들어 둡니다. 연수장에서 기다리면 첫 실습을 놓칩니다.

계정 세 개를 미리 만듭니다

GitHub

앱을 인터넷 주소로 바꿔 주는 곳입니다. 4칸에서 폴더를 올리면 GitHub Pages가 주소를 내어 줍니다.

사용자명은 영문 소문자와 숫자, 하이픈만 됩니다. 앱 주소에 그대로 붙으니 짧게 짓습니다.

GitHub 가입 페이지 열기

Google AI Studio

말로 앱을 만드는 작업실입니다. 2칸부터 7칸까지 여기서 앱을 만들고 배포까지 합니다.

반드시 개인 Gmail로 로그인합니다. 학교 계정은 막힙니다.

Google AI Studio 열기

Firebase

학생 30명이 같은 순위표를 보게 해 주는 서버입니다. 5칸에서 붙여 7칸까지 씁니다. 콘솔에서 스위치만 켜면 나머지는 AI가 붙입니다.

Firebase 콘솔 열기

  • AI Studio에 들어가면 로그인 창이 아니라 채팅 입력 칸이 나옵니다.
  • Firebase 콘솔에 프로젝트 목록이 열리고 결제 안내가 없습니다.
01

STEP 01

더 나은 바이브코딩을 위한 배경지식

실습이 없는 칸입니다. 시작하기 전에 판단할 네 가지를 정리합니다.

시작 전에 잡아 둘 네 가지

앱은 식당과 같습니다

홀

학생이 보고 만지는 화면입니다.

주방

선생님만 아는 저장과 계산입니다.

주문서

홀과 주방이 주고받는 정해진 양식입니다.

건물

앱이 사는 인터넷 주소입니다.

설계 목적 설정

누가, 어디서, 무엇을, 몇 분 안에 하는지를 한 줄로 적습니다. 4학년 25명이 전자칠판 앞에서 지도 퀴즈를 10분 안에 푼다. 이 한 줄이 프롬프트의 뼈대입니다.

누가 · 어디서

사람 수와 장소가 정해지면 화면과 글자 크기가 정해집니다.

무엇을

기능은 하나로 좁힙니다. 둘이 되면 완성까지 네 배 멉니다.

몇 분 안에

시간을 적어 두면 여기서 멈춰도 된다는 선이 생깁니다.

도구 선택

Canvas

Gemini 안에서 홀을 꾸밉니다. 앱 파일 한 개를 빠르게 뽑습니다.

AI Studio

API 키까지 주는 작업실입니다. 여러 파일로 된 앱을 다룹니다.

설치형 도구

학교 컴퓨터에 설치 권한이 없어 뺍니다.

고를 때는 설치 권한과 무료 조건, 한도를 봅니다.

과정

크게 한 번

무엇을, 어떻게 보이게, 누구를 위해 만드는지 처음 프롬프트에 적습니다.

백업 먼저

고치기 전에 파일을 복사해 index_백업.html로 남깁니다.

하나씩만

색을 바꿨으면 화면을 확인하고 그다음 글자 크기를 바꿉니다.

마인드셋

안 돼요 대신 어디까지 됐고 무엇이 나왔는지 말합니다. 세 번 막히면 백업 파일로 돌아갑니다.

오류 다루기

빨간 글씨는 한 글자도 바꾸지 말고 복사해 붙여넣습니다.

학생 정보

학생 이름과 얼굴은 올리지 않습니다. 학급 코드와 번호로 들어오게 합니다.

열쇠와 자료

API 키는 서버에만 둡니다. 교과서 자료가 든 앱은 교실 안에서만 씁니다.

시작하기 전 확인

  • 누가 어디서 무엇을 몇 분 안에 하는지 한 줄로 적었습니다.
  • 고치기 전에 백업 파일을 만들어 두었습니다.
  • 지금 한 번에 하나만 고치고 있습니다.
  • 화면과 파일에 학생 이름과 얼굴이 없습니다.
  • API 키가 코드 안에 적혀 있지 않습니다.
02

STEP 02

웹페이지 디자인 — 같은 내용, 다른 인상

만들기가 아니라 디자인 바꾸기입니다. 보이는 것만 바꾸고 문항도 정답도 손대지 않습니다.

왜 필요한가

바이브코딩 활동지는 누가 만들어도 비슷합니다. 디자인을 지시하지 않으면 AI의 기본값이 나옵니다.

DESIGN.md는 색과 글꼴, 간격 규칙을 마크다운 한 장에 적은 명세서입니다.

컨텍스트, 곧 맥락

컨텍스트(맥락)는 요청을 판단할 때 참고하는 배경입니다. 학년과 과목, 교실 환경, 학생 기기가 컨텍스트입니다.

배경을 주면 AI는 말하지 않은 것까지 채웁니다. 그래서 컨텍스트는 넓게 주고, 건드리지 말 것은 좁게 못박습니다. 문항과 정답은 바꾸지 말라고 적습니다.

이렇게 합니다

  1. Gemini Canvas에 활동지 프롬프트를 넣어 index.html 한 개를 만듭니다. 메모장에 저장할 때 파일 형식은 모든 파일, 이름은 index.html, 인코딩은 UTF-8입니다.

  2. 저장소의 demo/worksheet-before.html을 엽니다. 일부러 전형적으로 만든 4학년 사회 표본입니다. 앞 단계에서 실패했다면 이 파일로 3단계부터 이어갑니다.

    표본 활동지 열기

  3. 왜 다 비슷한지 눈으로 확인합니다. 보라색 그라데이션 배경 · 20px 라운드 카드 · 짙은 그림자 · 제목마다 붙은 이모지 · 전부 가운데 정렬 · 맨 아래 "Made with ♥ by AI" 한 줄.

  4. getdesign.md에서 명세를 고릅니다. 브랜드 명세 70여 종을 미리보기하고 복사합니다. 전자칠판에서 보이도록 대비가 뚜렷한 것을 고릅니다.

    getdesign.md 열기

  5. 활동지 HTML 전체와 DESIGN.md 전문을 넣고 아래 프롬프트를 붙여 넣습니다.

  6. 두 파일을 탭 두 개에 띄워 문항과 정답이 그대로인지 봅니다.

BEFORE

명세를 주지 않았을 때

AI의 기본값입니다.

AFTER

같은 문항, DESIGN.md를 건넸을 때

문항은 그대로이고 색과 여백, 글꼴이 바뀌었습니다. 삽화와 학습 목표, 구역 이름은 AI가 빈자리를 채운 것입니다.

복붙 프롬프트

아래 DESIGN.md에 맞춰 이 활동지를 다시 만들어 주세요.
문항과 정답은 하나도 바꾸지 말고 보이는 것만 바꿔 주세요.
완성된 index.html 전체를 생략 없이 코드블록 하나로 주세요.

--- DESIGN.md ---
[여기에 getdesign.md에서 복사한 DESIGN.md 전문을 붙여 넣습니다]

--- 활동지 HTML ---
[여기에 활동지 HTML 전체를 붙여 넣습니다]

이러면 성공입니다

  • 두 파일의 1번부터 4번까지 문항이 그대로입니다.
  • 보라색 그라데이션이 사라지고 배경이 한 가지 색입니다.
  • 제목에 이모지가 없는데도 무엇을 하는 화면인지 읽힙니다.

막히면

문항까지 바뀌어 버렸습니다

증상 디자인과 함께 문제 번호나 보기 문장까지 바뀌었습니다.

원인 바꾸지 말라는 문장이 없으면 AI는 다듬는 일까지 자기 몫으로 봅니다.

해결 위 프롬프트의 둘째 줄을 넣어 원본부터 다시 요청합니다.

코드가 중간에 잘렸습니다

증상 받은 코드 끝이 잘렸거나 중간에 생략 표시가 있습니다.

원인 생략 없이 전체를 달라고 하지 않으면 바뀐 부분만 보여 줍니다.

해결 "index.html 전체를 생략 없이 코드블록 하나로 주세요", 그래도 잘리면 "이어서 끝까지 주세요"라고 요청합니다.

글자가 깨져서 나옵니다

증상 브라우저에서 한글이 깨진 기호로 보입니다.

원인 메모장에서 저장할 때 인코딩이 UTF-8이 아니었습니다.

해결 메모장에서 다른 이름으로 저장을 눌러 인코딩을 UTF-8로 바꿉니다. 파일 형식은 모든 파일, 이름은 index.html입니다.

03

STEP 03

재료 만들어 붙이기 — 그리고 폴더가 되는 순간

그림과 소리 같은 재료(에셋)를 만들어 붙입니다. 이 칸을 지나면 앱 파일 한 개가 폴더로 바뀝니다.

왜 필요한가

앱 파일 한 개는 뼈대와 재료, 규칙이 한 장에 뭉쳐 있어 화면이 늘어나면 어디를 고칠지 알 수 없습니다. 앱이 되려면 역할이 다른 것들이 각자 자리로 흩어져 폴더에 모여야 합니다.

아래는 낚시 게임의 실제 파일 목록입니다.

파일이 늘어나는 것은 앱이 되었다는 뜻입니다
폴더와 파일역할식당 비유
index.html들어오는 문. 뼈대출입구
assets/재료. 그림과 소리홀의 인테리어
src/App.tsx엔진. 규칙과 계산이 도는 곳주방의 조리대
src/components/화면 조각. 기록표 창과 도감 창테이블과 메뉴판
src/index.css디자인 규칙인테리어 도면
firestore.rules누가 읽고 쓸 수 있는지출입 규정

BEFORE

AFTER

이렇게 합니다

  1. 파일이 여러 개가 되니 Canvas에서 AI Studio로 이사합니다. 채팅 규칙 칸(시스템 지시)에 "항상 index.html 전체를 코드블록 하나로, 생략 없이 주세요"를 적어 둡니다.

  2. 이미지 생성으로 재료를 한꺼번에 뽑습니다. 한 장씩 만들면 그림체가 달라집니다. 내려받은 파일은 assets 폴더에 넣고 fish-red.png처럼 영문 소문자로 바꿉니다. 한글 파일명과 띄어쓰기는 주소에서 깨집니다.

  3. AI에게는 그림 대신 경로를 알려 줍니다. assets/fish-red.png처럼 폴더 이름부터 쓰면(상대경로) AI가 그 자리에 그림을 끼웁니다.

  4. 효과음은 파일 없이 코드가 직접 만들게 합니다. 브라우저의 소리 기능(Web Audio)을 쓰면 파일명과 경로 문제가 사라집니다.

복붙 프롬프트

먼저 그림을 뽑습니다.

아래 조건을 모두 지켜서 낚시 게임에 쓸 물고기 그림을 만들어 주세요.
1. 스타일은 "납작한 벡터 일러스트, 굵은 검은 윤곽선"으로 모든 그림에 똑같이 적용합니다.
2. 배경은 흰색 단색으로 두고 그림자를 넣지 않습니다.
3. 물고기 네 종류를 한 장 안에 2x2로 배치합니다.
4. 이미지는 정사각형으로 만듭니다.

그림을 앱에 끼웁니다.

그림 재료를 assets 폴더에 넣었습니다. 아래 경로를 코드에 그대로 써 주세요.
assets/fish-red.png : 빨간 물고기
assets/fish-blue.png : 파란 물고기
assets/bg-sea.png : 바다 배경

지금 이모지로 그려진 부분만 위 그림으로 바꾸고, 게임 규칙은 하나도 바꾸지 마세요.
index.html 전체를 생략 없이 코드블록 하나로 주세요.

마지막으로 효과음입니다.

효과음은 파일을 쓰지 않겠습니다. Web Audio로 코드가 직접 소리를 만들게 해 주세요.
물고기를 낚았을 때 짧은 상승음, 놓쳤을 때 짧은 하강음 두 가지면 충분합니다.

이러면 성공입니다

  • assets 폴더에 파일이 3개 있습니다.
  • 파일 이름이 전부 영문 소문자입니다. 한글과 띄어쓰기가 없습니다.
  • index.html을 더블클릭하면 내가 만든 그림이 보입니다.

막히면

그림을 넣었는데 이모지가 그대로 보입니다

증상 코드는 바뀌었다는데 화면은 예전 그대로입니다.

원인 코드가 부르는 파일명과 실제 파일명이 다릅니다. 내려받을 때 이름 뒤에 숫자가 붙습니다.

해결 assets 폴더의 파일명을 코드와 똑같이 맞추고, 폴더가 index.html과 같은 자리인지 봅니다.

그림 자리가 깨져서 빈 칸으로 보입니다

증상 그림 자리에 테두리만 있거나 아무것도 없습니다.

원인 Fish.PNG와 fish.png는 인터넷 주소에서 서로 다른 파일입니다.

해결 파일명을 전부 소문자로 바꾸고 확장자가 png인지 jpg인지 코드와 맞춥니다.

파일이 여러 개로 늘어나서 당황스럽습니다

증상 앱 파일 한 개가 폴더와 파일 여러 개로 바뀌었습니다.

원인 실수가 아니라 앱이 되었다는 증거입니다.

해결 그대로 두고 4칸 주소 만들기로 갑니다. 앱 파일 한 개면 깃허브 페이지, 폴더면 ai.studio 주소로 올립니다.

04

STEP 04

주소 만들기

여기가 연수의 정점입니다. 지금까지 만든 앱에 인터넷 주소를 답니다. 주소가 생기면 QR 하나로 학생 30명이 같은 앱을 엽니다. 앱의 형태에 따라 길이 갈리니 어느 쪽인지 먼저 판단합니다.

왜 필요한가

지금 그 앱은 내 노트북에서만 열립니다. 파일이 그 안에만 있기 때문입니다.

STEP 05

서버 체험 — 게임과 기록표

게임을 만들어 점수를 서버에 올립니다. 링크만 보내면 다른 기기에서 같은 순위표를 보고, 내가 점수를 올리면 상대 화면이 새로고침 없이 바뀝니다. 학급 대항 순위표를 수업에 그대로 띄울 수 있습니다.

왜 필요한가

4칸에서 앱에 주소가 생겼습니다. 그런데 지금 앱이 기억하는 곳은 브라우저 안 저장 공간(localStorage)뿐이라 점수가 각자 기기에만 남습니다. 이번 칸에서 주방을 짓습니다. 실시간과 동시 접속이 붙어, 누가 점수를 올리면 30명의 순위표가 같은 순간에 바뀝니다.

이번에는 콘솔에 들어가 설정을 손으로 만지지 않습니다. AI Studio Build에게 말로 붙여 달라고 하면 연결과 익명 로그인, 규칙 파일까지 대화로 만들어집니다.

이렇게 합니다

  1. AI Studio의 Build에서 점수가 남는 게임을 만듭니다. 낚시 게임을 예로 듭니다. 그림과 소리는 3칸에서처럼 이미지 생성으로 한꺼번에 뽑아 넣습니다.
  2. 같은 채팅 칸에 아래 프롬프트를 넣습니다. Build가 Firebase 연결과 익명 로그인, firestore.rules, 실시간 갱신 코드까지 만듭니다.
  3. Firebase 설정 팝업이 뜨면 약관에 동의합니다. 이때 프로젝트가 자동으로 만들어집니다.
  4. 배포하고 링크를 공유합니다.

서버 연결하는 법

여기까지 오면 화면은 뜨는데 점수가 안 올라갑니다. 콘솔에서 익명 로그인을 켜야 합니다. AI가 대신 못 누르는 스위치 하나입니다.

익명 로그인을 켜는 네 단계
순서캡처보는 것
① Firebase 콘솔 홈 프로젝트 목록에 Default Gemini Project가 이미 있습니다. AI Studio Build가 만들어 둔 것이므로 새로 만들 필요가 없습니다.
② 왼쪽 메뉴 제품 카테고리를 펼치고 보안을 고른 다음 Authentication을 누릅니다.
③ 로그인 방법 탭 제공업체 목록에서 익명이 사용 설정됨으로 바뀌어 있어야 합니다.
④ 사용자 탭 접속자가 익명으로 쌓입니다. 학생 한 명이 들어올 때마다 한 줄씩 늘어나면 성공입니다.

순위표에 무엇이 보일지까지 정해 주면 화면이 한 번에 정리됩니다. 위 문장에 이어서 넣습니다.

한 판 했는데 기록이 안 올라옵니다

해결 Build에 규칙을 배포해 달라고 하거나 Firebase 콘솔의 Firestore 규칙 탭에서 게시를 누릅니다.

증상 다른 사람 화면에는 점수가 올라가는데 내 탭에서만 기록이 남지 않습니다.

원인 익명을 켜기 전에 열어 둔 탭이라 인증 객체가 null 로 남았습니다.

해결 그 탭에서 F5로 새로고침하면 인증을 다시 받습니다.

AI가 다 해 줘도 콘솔에서 사람이 눌러야 하는 스위치가 남습니다. 빨간 글씨는 요약하지 말고 그대로 복사해 AI에게 붙여넣습니다.

STEP 06

한 걸음 더 코딩 — 우리 반 사진 캘린더

여기부터는 단계를 일러 주지 않습니다. 미션과 지켜야 할 조건만 드립니다. 나머지는 스스로 풉니다.

왜 미션인가

5칸까지 오면서 만드는 법은 익혔습니다. 남은 것은 조건을 지키며 끝까지 가는 일입니다. 그건 따라 해서는 늘지 않습니다.

조건이 곧 설계입니다. 무료 범위와 개인정보가 무엇을 만들 수 있는지를 먼저 정합니다.

미션

우리 반이 함께 쓰는 달력을 만듭니다. 날짜를 누르면 사진 한 장이 올라가고, 다른 기기에서 열어도 같은 사진이 보입니다.

지켜야 할 조건

  1. 하루에 한 장만 남깁니다. 이미 있으면 바꿀지 먼저 묻습니다.
  2. 올리기 전에 정사각형 512픽셀 JPEG, 품질 0.7로 줄입니다.
  3. Firebase Cloud Storage를 쓰지 않습니다. 2026년 2월 3일부터 결제 계정이 있어야 만들 수 있습니다. 줄인 사진을 문자열로 바꿔 Firestore 문서에 넣습니다.
  4. 얼굴이 나온 사진은 올리지 않는다는 안내를 업로드 칸 위에 늘 띄웁니다.
막히면 여는 힌트

조건 세 가지를 프롬프트 문장에 그대로 넣지 않으면 AI는 원본 사진을 올리는 코드를 씁니다.

문서 하나의 한도는 1MB입니다. 512픽셀로 줄인 사진은 60KB에서 110KB입니다.

5칸에서 쓰던 Firebase 프로젝트를 그대로 씁니다. 익명 로그인은 이미 켜져 있습니다.

한 걸음 더 — 진짜 서버를 내 손으로

5칸의 Firebase는 AI가 붙여 주었습니다. 이번에는 내가 붙입니다. 같은 캘린더를 Supabase로 옮깁니다.

  1. supabase.com에서 프로젝트를 만듭니다. 카드가 필요 없습니다.
  2. Table Editor에서 photos 테이블을 만듭니다. 열은 day와 image, created_at 입니다.
  3. Settings의 API에서 Project URL과 anon public 키를 복사합니다.
  4. 아래 프롬프트로 앱을 연결합니다.
  5. 테이블에 RLS를 켜고 정책을 만듭니다. 켜지 않으면 링크를 아는 누구나 남의 사진을 지울 수 있습니다.

무료 프로젝트는 이레 동안 아무도 쓰지 않으면 잠깁니다. 방학이 지나면 멈춰 있으니 개학 전에 한 번 열어 깨웁니다.

조건 네 가지를 꼭 지켜줘.
1. 한 날짜에는 사진 한 장만 저장한다. 이미 있으면 바꿀지 먼저 물어본다.
2. 올리기 전에 브라우저에서 정사각형 512픽셀 JPEG로 줄이고 품질은 0.7로 한다.
3. Cloud Storage를 쓰지 말고 줄인 사진을 문자열로 바꿔 Firestore 문서에 저장한다.
4. 얼굴이 나온 사진은 올리지 않는다는 안내 문구를 업로드 칸 위에 항상 보이게 띄운다.
파이어베이스는 이미 붙어 있는 프로젝트를 그대로 써줘.

Supabase 연결 프롬프트

이 앱의 저장소를 Supabase로 바꿔 줘.

1. supabase-js는 CDN으로 불러온다. 빌드 도구는 쓰지 않는다.
2. 연결 정보는 코드 맨 위 한 곳에 모아 준다.
   const SUPABASE_URL = "[프로젝트 URL]";
   const SUPABASE_ANON_KEY = "[anon public 키]";
3. photos 테이블을 쓴다. 열은 day(날짜, 고유값), image(문자열), created_at(시각)이다.
4. 사진은 올리기 전에 정사각형 512픽셀 JPEG 품질 0.7로 줄여 문자열로 저장한다.
5. 같은 날짜에 이미 사진이 있으면 덮어쓸지 먼저 묻는다.
6. 다른 사람이 올린 사진도 새로고침 없이 보이도록 실시간 구독을 붙인다.

anon 키는 공개되는 값이야. 그래서 테이블에 RLS를 켜야 해.
읽기는 모두 허용하고 쓰기는 하루 한 장만 되도록 막는 SQL도 함께 줘.
그 SQL을 Supabase의 SQL Editor에 어떻게 붙여넣는지도 한 줄로 알려 줘.

스스로 확인

  • 같은 날짜에 두 번 올리면 바꿀지 묻습니다.
  • 다른 기기에서 열어도 같은 사진이 보입니다.
  • 사진이 모두 정사각형이라 달력 칸이 들쭉날쭉하지 않습니다.

막히면

사진이 안 올라갑니다

증상 파일을 고르면 멈췄다가 저장에 실패했다는 문구가 뜹니다.

원인 줄이기를 건너뛰고 원본을 올려 문서 한도 1MB를 넘겼습니다.

해결 512픽셀로 줄이는 단계를 넣어 달라고 다시 말합니다.

화질이 너무 나쁩니다

증상 사진이 뭉개지고 글씨가 찍힌 장면은 읽기 어렵습니다.

원인 512픽셀과 품질 0.7이 무료 조건 안의 상한입니다.

해결 더 키우면 저장이 통째로 실패합니다. 가까이에서 밝게 찍습니다.

남이 올린 사진이 지워집니다

증상 Supabase로 옮긴 뒤 아무나 사진을 지울 수 있습니다.

원인 RLS를 켜지 않았습니다. anon 키는 공개되는 값이라 키만으로는 아무것도 막지 못합니다.

해결 테이블에 RLS를 켜고 쓰기 정책을 만듭니다.

방학이 지나니 앱이 멈춰 있습니다

증상 잘 되던 캘린더가 오류만 냅니다.

원인 Supabase 무료 프로젝트는 이레 동안 아무도 쓰지 않으면 잠깁니다.

해결 대시보드에서 다시 켭니다. 개학 전에 미리 열어 둡니다.

07

STEP 07

한 걸음 더 코딩 — 앱이 AI를 부르게

마지막 미션입니다. 학생이 힌트 버튼을 누르면 앱이 대신 AI에게 묻습니다. 열쇠를 어디에 두느냐가 전부입니다.

왜 필요한가

앱이 AI에게 물으려면 API 키가 필요합니다. 앱 파일에 적어 두면 화면에 안 보여도 주소를 아는 사람은 꺼내 갑니다. 남이 쓴 만큼 내 한도가 줄어듭니다.

AI Studio Build는 이 구조를 이미 갖췄습니다. 키를 서버 쪽 비밀값으로 넣어 두고 호출은 서버가 대신 보냅니다. ZIP으로 내려받아 다른 곳에 올리는 순간, 그 일은 다시 내 몫이 됩니다.

미션

학생이 힌트 버튼을 누르면 AI가 한 문장으로 답합니다. 정답을 대신 말해 주지는 않습니다.

지켜야 할 조건

  1. 키 문자열이 학생 화면 어디에도 나오지 않습니다. 페이지 소스를 열어 직접 확인합니다.
  2. 힌트는 한 문장입니다. 정답을 그대로 말하지 않고 다음 한 걸음만 알려 줍니다.
  3. 한 사람이 연달아 누르지 못하게 막습니다. 무료 한도는 한 학급 한 수업 분량입니다.
  4. 모델은 gemini-2.5-flash-lite 를 씁니다.
무료로 쓸 수 있는 횟수
모델분당하루쓰임
gemini-2.5-flash 10회 250회 조금 더 똑똑한 답이 필요할 때
gemini-2.5-flash-lite 15회 1,000회 우리 반 앱 기본값. 힌트 한 문장에는 충분합니다
막히면 여는 힌트

5칸과 6칸에서 쓰던 프로젝트를 그대로 엽니다. 새로 만들지 않습니다.

키를 붙여넣을 칸을 찾지 못하는 것이 정상입니다. Gemini를 쓰는 앱이 되는 순간 AI Studio가 비밀값 패널에 키를 넣어 둡니다.

힌트가 너무 친절하면 프롬프트에 정답을 말하지 말라는 문장을 넣습니다.

출발 프롬프트

지금 문제 화면에 힌트 버튼을 하나 붙여 줘.
누르면 지금 풀고 있는 문제를 질문으로 만들어 Gemini에게 보내고
돌아온 답을 화면에 한 문장으로 보여 줘.

조건을 지켜 줘.
1. 정답을 그대로 말하지 말고 다음 한 걸음만 알려 준다.
2. 초등학생이 읽는 문장으로 쓴다. 한 문장을 넘기지 않는다.
3. 한 번 누르면 10초 동안 다시 못 누르게 막는다.
4. 모델은 gemini-2.5-flash-lite 를 쓴다.
5. API 키는 코드에 적지 않는다. AI Studio가 넣어 둔 서버 쪽 비밀값을 그대로 쓴다.

스스로 확인

  • 힌트 버튼을 누르면 한 문장이 돌아옵니다.
  • 페이지 소스를 열어 찾아도 키 문자열이 없습니다.
  • 연달아 누르면 잠시 막힙니다.

막히면

키를 어디에 넣어야 할지 모르겠습니다

증상 발급받은 키를 붙여넣을 칸이 없습니다.

원인 AI Studio Build에서는 칸이 없는 것이 정상입니다. 도구가 넣어 둡니다.

해결 비밀값 패널에서 키가 들어가 있는지만 확인합니다. 코드에 적지 않습니다.

하루 한도를 넘겼습니다

증상 오후가 되자 힌트가 오지 않습니다.

원인 무료 한도는 한 학급 한 수업 분량입니다.

해결 gemini-2.5-flash-lite 로 바꾸고 연달아 누르지 못하게 막습니다.

키가 새어 나간 것 같습니다

증상 쓴 적 없는 사용량이 잡힙니다.

원인 키가 코드나 캡처에 섞여 밖으로 나갔습니다.

해결 그 키를 즉시 지우고 새로 발급받습니다. 있어야 할 곳은 서버 쪽 비밀값 한 곳뿐입니다.

API 키

코드에 적지 않고 화면에 띄우지 않고 캡처로 공유하지 않습니다. 서버 쪽 비밀값으로만 둡니다. 새어 나갔다면 삭제하고 새로 만듭니다.

개인정보

학생 이름과 얼굴 사진은 공개 저장소에 올리지 않습니다. 회원가입 없이 학급 코드와 번호로 들어오게 하고 서버에는 번호와 별명, 점수만 남깁니다.

저작권

교과서 지문이나 삽화가 든 앱은 교실 안에서만 쓰고 공개하지 않습니다.

Public 저장소는 주소를 아는 누구나 들어옵니다. 학급 코드는 수업이 끝나면 바꿉니다.

공개 전 확인

  • 코드와 캡처 어디에도 API 키가 없습니다.
  • 학생 이름과 얼굴이 저장소에 없습니다.
  • 교과서 자료가 든 앱은 주소를 내지 않았습니다.
  • 학급 코드 바꾸는 곳을 확인했습니다.

LIMITS

무료로 어디까지 되나요

도구마다 하루에 쓸 수 있는 양이 정해져 있습니다. 2026년 9월 기준 값입니다.

도구 무료로 되는 범위 알아 둘 점
Gemini API 무료 등급은 Flash 계열만 됩니다. gemini-2.5-flash는 분당 10회에 하루 250회입니다. gemini-2.5-flash-lite는 분당 15회에 하루 1,000회입니다. 모델 이름을 어느 쪽으로 적었는지에 따라 한도가 네 배 차이 납니다.
Firebase Spark(무료) 결제 수단 없이 Firestore와 Hosting, Authentication을 씁니다. Firestore는 하루에 읽기 50,000회, 쓰기 20,000회, 삭제 20,000회까지 됩니다. 저장 공간은 1GB입니다. 5칸과 6칸이 이 범위 안에서 돕니다.
Firebase Cloud Storage 파일 업로드를 맡는 자리입니다. 2026년 2월 3일부터 버킷 생성에 결제 계정이 필요합니다. 이 페이지에서는 쓰지 않습니다. 6칸의 사진은 줄여서 Firestore에 문자열로 넣습니다.
GitHub Pages Public 저장소면 무료입니다. 4칸의 주소 만들기가 여기서 끝납니다.

한 학급 한 수업 분량은 가장 작은 칸에도 들어갑니다. 계산은 7칸 앱이 AI를 부르게에 있습니다.
